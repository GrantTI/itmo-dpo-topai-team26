# Методические указания преподавателям по использованию ресурсов
## Общие рекомендации

Данный раздел содержит рекомендации по подбору, подготовке и использованию информационных ресурсов для проведения лабораторных работ по дисциплине **«Разработка и развертывание клиент-серверных приложений с ML-компонентами»**.

Ресурсы сгруппированы по типам в папке [`resources/`](https://github.com/ssonnyas/itmo-dpo-topai-team26/tree/main/resources) и привязаны к конкретным модулям и лабораторным работам. Для каждого ресурса рекомендуется оформить карточку с полями:
- **Название** — точное наименование
- **Тип** — библиотека, датасет, инструмент, документация, статья
- **Аннотация** — краткое описание и назначение
- **Связанные КИМ** — ссылка на модуль или лабораторную работу
- **Доступ** — ссылка на ресурс
- **Лицензия** — условия использования
- **Дата проверки** — актуальность ресурса

---

## Ресурсы по модулям и лабораторным работам

### Модуль 1. Backend (36 часов)

| Тип ресурса | Название | Назначение | Ссылка |
| :--- | :--- | :--- | :--- |
| Библиотека | **FastAPI** | Основной веб-фреймворк для создания REST API | [fastapi.tiangolo.com](https://fastapi.tiangolo.com) |
| Библиотека | **Pydantic** | Валидация данных и создание схем | [docs.pydantic.dev](https://docs.pydantic.dev) |
| Инструмент | **Uvicorn** | ASGI-сервер для запуска FastAPI-приложений | [www.uvicorn.org](https://www.uvicorn.org) |
| Инструмент | **Swagger UI / OpenAPI** | Автоматическая документация API (встроена в FastAPI) | [swagger.io](https://swagger.io) |
| Библиотека | **pandas** | Обработка и анализ данных (загрузка CSV, статистика) | [pandas.pydata.org](https://pandas.pydata.org) |
| Библиотека | **scikit-learn** | Реализация ML-моделей, метрик, валидации | [scikit-learn.org](https://scikit-learn.org) |
| Документация | **C4 Model** | Нотация для описания архитектуры программных систем | [c4model.com](https://c4model.com) |

**Рекомендации по проведению ЛР модуля 1:**

1.  **Архитектура (Занятие 1.1):**
    *   Покажите студентам реальные продакшн-схемы с Backend, Frontend, Nginx и балансировщиком.
    *   Объясните, почему нотация C4 (уровни Context, Container, Component) важна для документирования архитектуры.
    *   Дайте задание нарисовать C4-диаграмму для своего будущего проекта в рамках дисциплины (модуль 4).

2.  **Разработка API (Занятия 1.2-1.6):**
    *   Акцентируйте внимание на **трехуровневой архитектуре**: маршруты (routers) → контроллеры → сервисы. Это ключевой паттерн для поддержки кода.
    *   Требуйте **централизованную обработку ошибок** через единый хендлер.
    *   Настаивайте на **полном документировании** всех эндпоинтов с помощью OpenAPI (Swagger). Это обязательное требование.
    *   Проверяйте, что API для моделей реализует эндпоинты для списка моделей, гиперпараметров и применения модели к данным.

3.  **Контроль самостоятельности:**
    *   Проводите короткие устные опросы по архитектуре кода перед началом каждой ЛР.
    *   Проверяйте понимание различий между контроллером и сервисным слоем.

### Модуль 2. Frontend (30 часов)

| Тип ресурса | Название | Назначение | Ссылка |
| :--- | :--- | :--- | :--- |
| Библиотека | **Axios** | HTTP-клиент для запросов к бэкенду | [axios-http.com](https://axios-http.com) |
| Библиотека | **ECharts** | Библиотека для построения интерактивных графиков (Actual vs Predicted, Residuals) | [echarts.apache.org](https://echarts.apache.org) |
| Библиотека | **Chart.js** | Альтернативная библиотека для графиков (более простая) | [www.chartjs.org](https://www.chartjs.org) |
| Инструмент | **Vue.js / React / Svelte** | (Выбор за преподавателем) Фреймворк для фронтенда | [vuejs.org](https://vuejs.org) / [react.dev](https://react.dev) / [svelte.dev](https://svelte.dev) |
| Инструмент | **Vite** | Сборщик для быстрой разработки фронтенда | [vitejs.dev](https://vitejs.dev) |
| Ресурс | **MDN Web Docs** | Документация по HTML, CSS, JavaScript | [developer.mozilla.org](https://developer.mozilla.org) |

**Рекомендации по проведению ЛР модуля 2:**

1.  **Интеграция с бэкендом (Занятие 2.2):**
    *   Покажите, как правильно организовать запросы к API через Axios.
    *   Объясните обработку асинхронных запросов (async/await, состояния загрузки, обработку ошибок на фронтенде).

2.  **Разработка интерфейсов (Занятия 2.3-2.4):**
    *   Основная задача — интерфейс для выбора ML-модели и отображения результатов.
    *   Сравните ECharts и Chart.js: ECharts предоставляет более богатые возможности для интерактивных графиков, Chart.js проще в освоении. Студенты должны выбрать инструмент под свою задачу.
    *   Обязательные графики: **Actual vs Predicted** (сравнение реальных и предсказанных значений) и **Residuals** (график остатков).

3.  **Самостоятельная работа (Занятие 2.5):**
    *   Студенты должны реализовать переключение между моделями и интерактивные графики. Это хороший материал для портфолио.

### Модуль 3. Интеграция и развертывание (20 часов)

| Тип ресурса | Название | Назначение | Ссылка |
| :--- | :--- | :--- | :--- |
| Инструмент | **Docker** | Контейнеризация приложения | [www.docker.com](https://www.docker.com) |
| Инструмент | **Docker Compose** | Оркестрация нескольких контейнеров (backend, frontend, nginx) | [docs.docker.com/compose](https://docs.docker.com/compose) |
| Инструмент | **Nginx** | Веб-сервер, reverse-proxy, балансировка | [nginx.org](https://nginx.org) |
| Инструмент | **GitHub Actions / GitLab CI** | CI/CD для автоматической сборки и деплоя | [github.com/features/actions](https://github.com/features/actions) |
| Документация | **Dockerfile Best Practices** | Рекомендации по написанию эффективных Dockerfile | [docs.docker.com/develop](https://docs.docker.com/develop) |
| Инструмент | **Portainer** | Визуальное управление Docker-контейнерами | [www.portainer.io](https://www.portainer.io) |

**Рекомендации по проведению ЛР модуля 3:**

1.  **Интеграция (Занятие 3.1):**
    *   Ключевая задача — согласовать контракт REST API между клиентом и сервером.
    *   Объясните концепции CORS и reverse-proxy. Покажите, как настраивать прокси для разработки (через Vite) и для продакшна (через Nginx).

2.  **Развертывание (Занятия 3.2-3.3):**
    *   **Многостадийная сборка (multi-stage build)** в Docker — обязательный элемент для продакшн-образов. Покажите, как разделить стадии сборки и запуска для уменьшения размера образа.
    *   Настройка **переменных окружения** для разных сред (dev, prod).
    *   Продемонстрируйте настройку **reverse-proxy** и **балансировки** на Nginx.

3.  **Самостоятельная работа (Занятие 3.4):**
    *   Студенты должны самостоятельно собрать Docker-образы и запустить проект в production-режиме. Проверьте, что приложение доступно извне и все компоненты взаимодействуют корректно.

### Модуль 4. Проектная работа (22 часа)

| Тип ресурса | Назначение |
| :--- | :--- |
| **Весь стек из модулей 1-3** | Интеграция всех компонентов в единое приложение |
| **Репозиторий на GitHub** | Размещение кода проекта, документация |
| **Презентационные материалы** | Подготовка слайдов для защиты проекта |
| **Документация проекта** | Описание архитектуры, API, инструкции по развертыванию |

**Рекомендации по проведению защиты проекта:**

1.  **Требования к проекту:**
    *   Приложение должно быть полностью работоспособным.
    *   Должна быть C4-диаграмма (хотя бы уровни Context и Container).
    *   Документированный API (OpenAPI).
    *   Возможность развертывания через Docker Compose.

2.  **Защита:**
    *   Уделите внимание не только коду, но и **обоснованию выбора инструментов** (почему FastAPI, почему ECharts, почему Nginx).
    *   Задавайте вопросы по каждому модулю, чтобы проверить целостность знаний.
    *   Оценивайте архитектурные решения, качество кода и удобство пользовательского интерфейса.

## Общие рекомендации по проведению занятий

### Подготовка среды
-   Предоставьте студентам `requirements.txt` для бэкенда и `package.json` для фронтенда.
-   Рекомендуйте использовать **Python 3.10+** и **Node.js 18+**.
-   Для модуля 3 убедитесь, что на компьютерах установлены Docker и Docker Compose.
-   Студенты могут использовать **Google Colab** или локальную среду с GPU, если потребуется обучение моделей.

### Контроль самостоятельности
-   Проводите **устные защиты** после каждой лабораторной работы.
-   Проверяйте понимание кода, а не только его наличие.
-   Ведите журнал частых ошибок для улучшения заданий в будущем.

### Использование LLM (ChatGPT, Copilot)
-   **Разрешите** использование LLM для:
    -   Объяснения синтаксиса.
    -   Отладки ошибок.
    -   Генерации шаблонного кода.
-   **Запретите** полное решение задания через LLM. Студент должен понимать каждую строчку итогового кода.
-   **Требуйте** указывать, если студент использовал LLM для значимой части работы.

### Обратная связь
-   Комментируйте код в Pull Request’ах с конкретными рекомендациями.
-   Указывайте на типовые ошибки всей группе на общих занятиях.
-   Поощряйте студентов вести собственный журнал ошибок и решений.
