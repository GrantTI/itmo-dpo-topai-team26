# Методические указания для преподавателей по оцениванию модуля «Интеграция и развёртывание»

## 1. Общие положения

Настоящие методические указания предназначены для преподавателей, осуществляющих оценивание результатов освоения модуля 3 дисциплины «Разработка и развертывание клиент-серверных приложений с ML-компонентами».

Модуль включает пять видов аттестационных мероприятий (итого **50 баллов**):

| КИМ | Занятие | Макс. | Зачёт от | Файл КИМ |
|---|---|---:|---:|---|
| Сравнительно-аналитическое эссе | 3.1–3.2 | 5 | 3 | [kim-05](../../M3-integration-deployment/kim-05-essay-integration-patterns.md) |
| Лабораторная работа: интеграция клиента и сервера с моделью | 3.3 | 10 | 6 | [kim-01](../../M3-integration-deployment/kim-01-labrab-client-server-integration.md) |
| Лабораторная работа: Docker / Compose / Nginx | 3.4 | 10 | 6 | [kim-02](../../M3-integration-deployment/kim-02-labrab-production-compose.md) |
| Лабораторная работа: Nginx advanced + multi-stage | 3.5 | 10 | 6 | [kim-03](../../M3-integration-deployment/kim-03-labrab-nginx-multistage.md) |
| Самостоятельная работа: развёртывание своего проекта | 3.6 | 15 | 9 | [kim-04](../../M3-integration-deployment/kim-04-srs-project-deploy.md) |

Критерии и показатели зафиксированы в соответствующих КИМ; ниже приведены шкалы и акценты проверки для быстрой работы на занятии. Методические указания обучающимся: [students](../students/README.md).

**Порядок сдачи (рекомендуемый):** эссе → ЛР 3.3 → ЛР 3.4 → ЛР 3.5 → СРС 3.6. Допускается параллельная доработка эссе после 3.3, если на защите 3.3 обучающийся кратко формулирует паттерн in-process.

**Рабочий паттерн учебного стенда:** инференс внутри серверной части модуля 1 (in-process). Отдельный контейнер inference не требуется.

## 3. Оценивание лабораторной работы 3.3 (интеграция с моделью)

Максимум — **10 баллов**; зачёт — не ниже **6**. Обязателен **письменный отчёт** и демонстрация **из UI**.

| Критерий | Баллы |
|---|---:|
| Контракт и конфигурация адреса API | 0–2 |
| CORS и/или прокси разработки | 0–2 |
| Сквозной сценарий с моделью из UI | 0–4 |
| Устойчивость клиента и обоснование | 0–2 |
| **ИТОГО** | **10** |

**Процедура защиты:**

1. Обучающийся запускает клиент и сервер, показывает сценарий с моделью из интерфейса.
2. Преподаватель проверяет единую настройку базового URL и работоспособность запросов (CORS/proxy, в том числе унаследованные из модуля 2).
3. Уточняющие вопросы: путь запроса, место выполнения инференса, реакция UI при недоступности API.

**Акцент:** новый обязательный результат — сценарий с моделью из UI, а не повторная настройка CORS «с нуля».

## 4. Оценивание лабораторной работы 3.4 (Compose + Nginx)

Максимум — **10 баллов**; зачёт — не ниже **6**. Объект — **учебный стенд** (не обязательно свой репозиторий).

| Критерий | Баллы |
|---|---:|
| Сборка образов | 0–2 |
| Оркестрация сервисов | 0–2 |
| Конфигурация окружения | 0–2 |
| Публикация и проверка контура (smoke через Nginx к API модели) | 0–2 |
| Обоснование решения | 0–2 |
| **ИТОГО** | **10** |

**Процедура защиты:** `compose up` → UI через Nginx → smoke-тест метода, связанного с моделью → вопросы по пути запроса и составу сервисов. Секреты в репозитории — 0 по критерию окружения.

## 5. Оценивание лабораторной работы 3.5 (Nginx + multi-stage)

Максимум — **10 баллов**; зачёт — не ниже **6**. Опора на контур 3.4.

| Критерий | Баллы |
|---|---:|

**Процедура защиты:** показать обновлённый Nginx и Dockerfile, продемонстрировать схему «один из пунктов 1–2 + второй из 1–3» по заданию КИМ, повторить smoke через Nginx.

## 6. Оценивание самостоятельной работы 3.6 (свой проект)

Максимум — **15 баллов**; зачёт — не ниже **9**. Объект — **собственный** проект дисциплины.

| Критерий | Баллы |
|---|---:|
| Полнота контура | 0–5 |
| Воспроизводимый запуск (UI + smoke API модели) | 0–5 |
| Описание контура | 0–3 |
| Корректность конфигурации | 0–2 |
| **ИТОГО** | **15** |

**Граница с модулем 4:** в 3.6 оценивается воспроизводимый контейнерный контур. Критерий 6 проекта (промышленные практики / развёртывание) опирается на уже принятый контур 3.6 и не дублирует полный балл за ту же сдачу. Не оцениваются в 3.6: качество обучения моделей, UI-дизайн, покрытие тестами, презентация защиты проекта.
