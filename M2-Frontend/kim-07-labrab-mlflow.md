# Лабораторная работа: Интеграция MLflow с клиент-серверным приложением

## 1. Цель работы
Разработать клиент-серверное приложение для управления ML-моделями с интеграцией MLflow, реализовать мониторинг качества моделей и оценить эффективность инженерных практик промышленной разработки систем ИИ.

## 2. Достигаемая компетенция
**LC-5.1.** Тестирует, испытывает и оценивает качество инструментов и инженерных практик промышленной разработки систем ИИ, развертывания и сопровождения моделей МО в рабочей версии ПО.

## 3. Технологический стек
- **Frontend:** Vue.js 3, Chart.js
- **Backend:** FastAPI
- **ML-платформа:** MLflow (Tracking Server + Model Registry)
- **Контейнеризация:** Docker, Docker Compose
- **Мониторинг:** Prometheus

## 4. Задачи для выполнения

### 4.1. Настройка инфраструктуры
- Развернуть MLflow Tracking Server с использованием Docker Compose.
- Настроить Model Registry для управления версиями моделей.
- Организовать хранение артефактов (моделей, метрик, параметров).

### 4.2. Разработка ML-компонента
- Обучить классификационную модель с использованием scikit-learn.
- Зарегистрировать модель в MLflow Model Registry с логированием:
  - Параметров обучения (гиперпараметры)
  - Метрик качества (accuracy, precision, recall, f1)
  - Артефактов (модель, предобработчик данных)
- Выполнить переход модели между стадиями жизненного цикла (Staging → Production).

### 4.3. Разработка Backend (FastAPI)
Реализовать REST API для:
- Получения списка моделей из Model Registry с фильтрацией по стадии
- Выполнения инференса через загруженную модель
- Перемещения модели между стадиями
- Получения истории производительности модели
- Сравнения метрик нескольких моделей
- Настроить CORS для взаимодействия с фронтендом.
- Реализовать кеширование загруженных моделей для оптимизации производительности.

### 4.4. Разработка Frontend (Vue.js)
- Разработать компонент выбора модели, отображающий:
  - Список моделей с версиями и стадиями
  - Метрики производительности
  - Возможность переключения стадии модели
- Реализовать форму для выполнения предсказаний с:
  - Динамическими полями для признаков
  - Валидацией входных данных
  - Отображением результата предсказания
- Создать дашборд мониторинга с использованием Chart.js:
  - График динамики метрик по версиям модели
  - Диаграмма сравнения метрик нескольких моделей
  - Визуализация дрейфа данных (PSI)

### 4.5. Тестирование и оценка
- Провести интеграционное тестирование всех компонентов системы.
- Выполнить нагрузочное тестирование эндпоинта предсказаний.
- Оценить качество работы системы по метрикам:
  - Время ответа API (< 200 мс)
  - Успешность запросов (> 99%)
  - Точность модели (> 0.8)

## 5. Отчет по работе
Отчет должен содержать следующие разделы:

1. **Архитектура системы** — схема взаимодействия компонентов с описанием потоков данных.
2. **Конфигурация MLflow** — описание настроек сервера, структуры экспериментов.
3. **Реализация API** — спецификация эндпоинтов с примерами запросов/ответов.
4. **Интерфейс пользователя** — скриншоты с описанием функциональности.
5. **Результаты тестирования** — таблицы с метриками производительности.
6. **Анализ инженерных практик** — таблица сравнения инструментов с обоснованием выбора MLflow.
